# Playbook：前端、状态、可访问性、响应式

前端缺陷多数不会被集成测试抓到（集成测试打 API，单测 stub 了 fetch）。逐项检查时优先用"读代码 + 组件测试 + 静态推导"，GUI/真机类结论一律标注未验收。

## 1. 入口与全局

- `src/web/main.tsx`：Provider 层次、`defaultColorScheme` 是否被服务端设置覆盖（**服务端主题要在启动时生效**，而不是只在设置页保存后）；查询客户端默认 `retry`/`staleTime`。
- `src/web/App.tsx`：路由懒加载、`Suspense` 兜底、`Placeholder` 兜底页、skip link、`main` 的 `tabIndex`。
- 导航可达性：手机（`< sm`）隐藏侧栏后，每个页面是否仍能到达（动作库等次级入口）。检查 `src/web/styles.css` 的媒体查询与 `AppShell` 配置是否互相矛盾。

## 2. 数据层与 API 契约

- 每个 `useQuery` 的 `queryKey` 必须覆盖全部筛选参数，否则筛选切换会读到脏缓存。
- 变更后 `invalidateWorkouts` 的失效范围是否覆盖列表、详情、统计、metadata；有没有漏掉某个查询键。
- `src/web/lib.ts` 的错误映射：401/403、412、429、网络失败、非 JSON 响应（Access 登录页）、响应 schema 不符各有不同文案与"是否保留输入"的语义；新增状态码时要检查分支是否漏。
- 响应必须用共享 schema 解析（`safeParse`），不得 `as` 断言。

## 3. 乐观锁、幂等与草稿（本项目最易出错的部分）

- 编辑必须带客户端读到的 `version`（`If-Match`），412 时**保留本地输入**并禁止直接覆盖；检查有没有"先查询再无条件写入"的写法。
- 提交不确定（网络失败）时：保留原 `Idempotency-Key` 与原正文，优先重放；只有服务端明确拒绝（400/404/409/413/422）才允许解锁修改。
- 本地草稿：每个 document 独立 key（不复用 sessionStorage ID）；恢复是**显式复制**到当前 key，不删除来源；提交成功后只删当前副本；损坏草稿不得覆盖现有输入；`localStorage` 配额/禁用错误必须被捕获并提示；过期策略（新建草稿 30 天）要明示。
- 多标签：`storage` 事件的处理是否会导致静默互相覆盖；关闭/离开前的提示（`beforeunload`、导航 blocker）条件是否正确。
- 退出流程：是否清理本地草稿与内存缓存，并引导结束 Access 会话。

## 4. 表单与校验

- 客户端校验必须复用服务端同一 schema；任何"前端另写一套规则"都要核对是否漂移。
- 校验失败必须定位到具体字段（`form.setFieldError`）并把焦点移到错误摘要/字段，错误文案要能让用户知道改什么。
- 字段级错误关联（`aria-invalid`、`aria-describedby`）；数值输入要有合适的 `inputMode`，触控目标 ≥ 44px。
- 空值语义：空白代表未记录、`0` 代表明确零值，UI 文案与占位符不得混淆两者。
- 计量口径提示（单只重量、每侧次数、辅助重量不是外加重量、热身/正式）必须与实际计算一致。

## 5. 状态与反馈完整性

每个数据页都要有：加载中、空、失败（可重试）、保存中、冲突/未同步。检查是否存在只弹一次 toast 却没有持久状态提示的流程。冲突状态必须有可访问的出口（查看云端、放弃本地并重载），不能只有"重试"。

## 6. 图表与统计展示

- 图表必须带范围、单位、定义版本、有效样本数与可访问明细表；图表与明细必须同源。
- 缺失值不连线、不当作零；单点不暗示趋势；颜色不得是唯一区分手段（线型/标签/符号）。
- 统计响应里的 `quality.missing`/`quality.excluded` 键必须都有中文标签——新增后端键名时检查前端标签字典是否漏项（否则界面直接显示英文键）。

## 7. 可访问性与响应式

- 键盘可完成关键流程（新建训练、逐组录入、保存、删除确认）；焦点在弹窗关闭后回到触发按钮。
- 200% 缩放与 360/390/768/1024/1440 px 下无横向溢出、无按钮被底部导航或保存栏遮挡；安全区 `env(safe-area-inset-*)` 已处理。
- 大表格在手机上要么转卡片、要么局部横向滚动，页面本身不得横向滚动。
- 明暗主题、焦点可见、错误/空状态对比度。
- 取证限制：`renderToStaticMarkup` 的字符串断言、JSDOM 组件测试、Playwright WebKit 都不能替代真机与真实视口验收，报告里必须写明"未验收"。

## 8. 性能与体积

- 次级页面（趋势、设置）是否路由拆包；图表库是否按需；有没有把整个图表库打进首屏。
- 记录 build 输出的主包/CSS/路由块体积，与上一轮比较；显著增长要给出原因。
- 不在首次渲染发重复请求；列表不默认加载全部明细。
